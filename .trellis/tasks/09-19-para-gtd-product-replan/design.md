# Design：Cortex 展现换壳（工作流优先）

> 配套 `prd.md`。本文件只谈信息架构与界面结构，不谈字段实现细节。

---

## 1. Design problem

现状壳层在教用户「你在哪个滴答模块」。目标壳层应教用户「你在工作流的哪一步」。

成功标准：去掉左轨后，第一屏仍一看就是 Cortex（项目—下一步—今天），而不是通用待办三栏。

---

## 2. Navigation

### 2.1 Primary (always visible)

| 项 | 角色 | 空态文案方向 |
| --- | --- | --- |
| 今天 | 默认首页；日期承诺的下一步 | 「今天还没有承诺。处理收集箱或给下一步一个日期。」 |
| 收集箱 | 未处理；>0 强调 | 「收好了。有空再处理。」 |
| 下一步 | 所有可动手未完成 | 「没有可动手的事。是真闲，还是都在等待？」 |
| 项目 | 进行中容器列表 | 「建一个有结束线的盒子，并写下第一刀。」 |

「处理」不是常驻第四个并列项时：作为收集箱上的主按钮进入全屏/中栏模式。

### 2.2 Tools (secondary)

日历（月/周）、摘要、搜索、设置。图标可保留，但视觉权重低于工作流。

### 2.3 Archive (collapsed)

已完成、放弃、垃圾桶。

### 2.4 Explicit removals from default chrome

- 左轨「任务 / 日历 / 习惯」并列身份
- 侧栏底部常驻迷你月历（改为日历工具页内控件，或设置开关默认关）
- 习惯作为与任务同级的产品柱（改为今天页底部条 + 工具里的习惯列表）

---

## 3. Core surfaces

### 3.1 今天

- 按**项目**分组；无项目 →「独立」组。
- 每条必须已处理且日期落在今天。
- 习惯条在列表下方，只读或轻量勾选，不抢主列表。
- 添加：默认已处理 + 今天日期；禁止静默变成未处理收集项。

### 3.2 收集箱 → 处理模式

- 浏览模式：普通列表。
- 处理模式：一次一条，大标题，少动作：现在做 / 挂项目 / 变项目 / 独立下一步 / 设日期 / 扔掉。
- 键盘优先（见 PARA PRD）。清到 0 给一句安静反馈。

### 3.3 项目页

- 顶：名称、完成定义、状态、缺下一步警告。
- 中：可动手下一步 → 等待中 → 已完成折叠。
- 加号：默认本项目下一步。

### 3.4 日历（工具）

- 保留月/周、跨天条、拖拽改期。
- 右侧无日期队列改称「未排期下一步」，数据来自下一步 ∩ 无日期；不要「安排任务」营销感文案。
- 进入路径：工具区或今天「看本周闲忙」。

## 4. Visual language (Web Interface Guidelines)

| 主题 | 应用 |
| --- | --- |
| 轻选中 | 继续细环 / 下划线；禁止粗黑饼抢注意力 |
| 焦点 | `:focus-visible` 可见；不靠粗 border 冒充选中 |
| 数字 | `tabular-nums`；展示日期用 `Intl`（zh-CN） |
| 长文本 | 标题/备注截断或 `overflow-wrap` |
| 动效 | 只动 transform/opacity；尊重 `prefers-reduced-motion` |
| 文案 | 中文主动句；占位符用「…」；错误带下一步 |

品牌：墨纸暖底已有；换壳时**加强工作流信息层级**，不新开紫渐变/卡片墙。第一屏应能通过「今天 + 项目分组」辨认 Cortex，而不是靠迷你月历。

| 日期 | 决策 | 选择 |
